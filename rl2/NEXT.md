# PoG RL — 后续实验议程

基于 `REPORT.md` 两部分的发现（belief 共享梯度有害且已定位为梯度干扰；截断理性获证；课程递进收益最大），按「每 CPU/GPU 小时回答多少问题」排序。

## 第一梯队：直接续接本次发现（合计约一晚）

### ① 信念作为输入，而非损失（belief-as-input）★首推
- **假设**：信念**信息**有价值，此前受害于**梯度**路径。
- **设计**：冻结 C-sg 的猜牌头，将其 65 维概率输出拼进策略观测（OBS_DIM 603→668），从 B-full 热启动训练一臂，对打 B-full。
- **判定**：若仍不涨，才可下结论"信念信息对棋力无用"；若涨，得到无痛集成方案。
- **成本**：小改 rollout.js/model.py + 2×150min。

### ② 补 A-full（无 GRU 全战役对照）
- **缺口**：GRU 在 3 回合打平被归因"时程太短"，但全战役从未训过无 GRU 臂。
- **设计**：A 热启动 → 150min 全战役 → vs B-full 60 局。
- **判定**：20 回合下记忆是否值 45% 迭代开销。

### ③ 主结论多种子重复
- B-full 62:38 C-full 仅单种子 p≈0.046。换 2–3 种子重训该对臂（~8h），把"发现"升级为"结论"。

## 第二梯队：棋力工程

### ④ 特权 Critic 蒸馏 → 搜索叶子（重做 D 臂）
- 蒸馏 Critic 为部分观测小价值网（JS 可跑），替换 D 臂搜索的启发式叶子，重测信念确定化搜索的真实增益；顺带产出可部署的"策略+搜索"最强体。

### ⑤ 人类评测
- 把 B-full（或 ④ 产物）部署进网页版（jsnn.js 浏览器推理现成），真人对局——回答"能否与一般玩家对打"的唯一途径。

## 第三梯队：更大的题

- **⑥ λ_B 扫描**（0.05/0.1/0.2）：小权重下共享梯度 belief 是否翻转为正则化收益
- **⑦ 学派种群**：不同对手池/课程养 CP-West、CP-East、CP-Risk 等，cross-play 鲁棒性矩阵
- **⑧ League 消融**：纯镜像 vs 70/20/10，league 是否真防循环克制
- **⑨ GNN 编码器**：point-to-point 图归纳偏置替代扁平特征（需重写 JS 前向）
- **⑩ NFSP / Deep CFR 对比**：论文级工作量，最后做

## GPU（RTX 3050 6GB）迁移备忘

**先说关键**：当前管线的瓶颈是 **JS 模拟器 + 轨迹序列化（CPU）**，不是网络训练——50 万参数的小网在 M1 CPU 上更新只占迭代时间的一小半。插上 3050 后若只把 torch 挪到 CUDA，收益有限。真正的提速路径按优先级：

1. **放大网络**（GPU 的正确用法）：hidden 128→512、GRU→2 层或小 Transformer、加 ⑨ 的 GNN——6GB 足够放千万参数级模型；此时 GPU 训练才成为收益项。
2. **提高模拟吞吐**：rollout 工作进程数拉满 CPU 核（GPU 机器通常核更多）；把轨迹格式从 JSONL 换成二进制（npy/arrow），当前解析开销约占迭代 1/4。
3. **批量推理**：多局并行时把各局的 obs 攒批发 GPU 推理（需把 jsnn 推理改为 python 侧 socket 服务或 onnxruntime-node + CUDA EP），自对弈能再快 2–5×。
4. 显存参考：现网络全量训练 <1GB；512 宽 + 2 层 GRU + batch 按 episode ≈ 2–3GB，6GB 无压力。
5. `pip install torch --index-url https://download.pytorch.org/whl/cu121`（Windows/Linux）；模型 JSON 导出与 JS 端完全不变，管线其余零改动。
